## 生成命令

```bash
python src/train.py --dev-frac 0.15 --out artifacts/l0 --soft-labels
python src/evaluate.py --bundle artifacts/l0_v3/bundle.joblib --split test \
       --dump submissions/submission_test_v3.json
python analysis/check_submission.py submissions/submission_test_v3.json    # 格式校验
python analysis/answer_defects.py                                          # 客观缺陷检查
```

## 与提交要求的对应关系

按 `提交要求.md`，每个条目包含 5 个字段：

| 字段 | 取值 | 本方案的处理 |
|---|---|---|
| `sample_id` | 全局唯一 | 直接沿用测试集 `问题.json` |
| `answer` | 回答文本；证据不足时 `无法确定` | 模板式组装（检索 + 链槽位替换）或抽取式（默认关闭） |
| `evidence_chain` | 原因→结果顺序的事件 ID 列表；无法确定时为空 | 链解码器的 top-1 输出 |
| `confidence` | 0~1；无法确定时为 `null` | 置信度模型输出向 0.7 收缩 75% |
| `question_type` | `retrospective` / `prospective` / `counterfactual` | 数据集里的 `unanswerable` 等取值统一归到 `retrospective` |

## 两点必须知道的限制

1. **C 档（200 题）没有事件列表**，流水线退化为"一文档一事件"建图（`materialize_events_from_docs`）。
   这是通用兜底，不是文档级事件抽取模型——C 档的实际水平没有金标可验证，风险最高。
2. 本文件是用**我们自己复刻的评分器**调出来的配置生成的；官方评分脚本未公开，
   绝对分不可比，只能横向比版本（详见 `docs/结果_L0.md`）。
