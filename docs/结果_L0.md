# L0（纯 CPU）基线结果

## 1. 这套东西是什么

不训练任何生成模型，全部用 sklearn 在 CPU 上跑。五个可训练模块 + 通用图解码：

| 模块 | 模型 | 训练耗时 |
|---|---|---|
| 意图分类 IntentModel | 字符 TF-IDF(1-3gram) + 逻辑回归 | 5 s |
| 拒答判定 AbstainModel | 字符 TF-IDF + 逻辑回归 | 1 s |
| 因果边 EdgeModel | GBDT(140 树) × 12 特征（B/C 档建图用） | 14 s |
| 链排序 MoEChainRanker | GBDT(260 树) × 28 特征，按预测意图分流 9 个专家 | 215 s |
| 置信度 ConfidenceModel | GBDT(120 树) → certain/probable/possible | 3 s |
| 答案组装 AnswerBank | 非参数检索 + 链槽位替换（无参，不训练） | 0 s |

总计：**851 个训练 pack，全部训练 4.5 分钟，1081 题推理 4 分钟**（CPU）。

## 2. 当前指标

dev = 149 个按领域分层的留出 pack（1081 题），全部为 A 档分布（给了事件+因果边）。

| 口径 | 答案(40) | 证据链(40) | 置信度(20) | 总分 | 金标上界 | 相对达成 |
|---|---|---|---|---|---|---|
| A 档（给边） | 23.07 | 35.35 | 18.13 | **76.55** | 90.36 | **84.7%** |
| B 档模拟（抽掉边，用预测边重建图） | 22.02 | 32.58 | 18.04 | **72.64** | 90.36 | **80.4%** |

"金标上界"= 把标准答案和标准证据链直接当预测喂进评分器得到的分数。
它不等于 100 是因为本仓库的评分器是**代理实现**（官方脚本未公开）：语义相似度用字符
n-gram 近似，`required_facts` 这类"判分要点"与答案正文措辞不一致，表层匹配天生有
约 10% 的漏判（实测正例命中率上限 0.90）。因此**相对达成率比绝对分更可信**。

预期比赛综合分（A 60% / B 30% / C 10%）：A、B 两项加权已 ≈ 67.7，C 档另计。

## 4. 迭代过程（每一步都是可复现的实验）

| 版本 | 改动 | A 档总分 | 备注 |
|---|---|---|---|
| v0 | 按意图写死"该生成什么形状"的候选生成器 | 66.99 | 预测题链准确率 0.000 |
| v1 | 生成器改为**枚举通用形状**（8 类），长度上限 5→8，新增 28 维形状特征 | 73.43 | 预测题 0.000→0.656；推理提速 3 倍 |
| v2 | 排序器改为**按预测意图分流的混合专家**（1 全局 + 9 专家） | 76.15 | 单跳 0.602→0.801 |
| v3 | 拒答阈值 0.5→0.7、置信度向先验收缩 0.75 | **76.55** | — |

## 5. 两个诚实的负面结论

1. **置信度模型的排序能力不如常数。** dev 上扫参：模型原始输出 17.97/20，
   恒输出 0.7 得 18.48/20。也就是说现有特征（候选形状 + 意图 + P(拒答)）不足以
   预测"这题我答得对不对"。目前退化为"向 0.7 收缩 75%"（76.80 vs 恒定的 76.89，
   差异在噪声内），真正的置信度校准需要引入"答案与证据的自一致性"这类信号。
2. **答案分被评分器低估。** 我们的答案组装是在金标上界只有 31.01/40 的口径下拿到
   23.07，占上界的 74%；换成官方脚本或更语义化的判定后，绝对分预计会更高。

## 6. 下一步（按性价比排序）

1. multi_hop 候选召回 0.850 是硬上限——补通用路径枚举（更长路径 / 受限 k-best）。
2. 答案组装：把"检索 + 槽位替换"升级为"检索 k 条 + 学习式选择/融合"。
3. 置信度：加入自一致性特征（同一问题的多种改写是否给出一致的链）。
4. 事件抽取（C 档没有事件列表）：文档级事件抽取，用 3B 模型 LoRA 或
   序列标注小模型；这是 C 档唯一的入口。

## 7. 复现命令


## 8. 迁移性审计（回答"换数据集还灵不灵"）

### 8.1 消融：分数有多少是靠本赛题数据的结构性痕迹拿到的？

dev = 149 pack / 1081 题，A 档口径，基线 76.55。

| 消融 | 做法 | 答案 | 证据链 | 总分 | 相对基线 |
|---|---|---|---|---|---|
| 基线 | — | 23.07 | 35.35 | **76.55** | — |
| 去文档顺序类特征 | 置零 8 个依赖"文档编号/时间先后/首末位置"的特征 | 23.10 | 33.94 | **75.14** | −1.41 |
| 去锚点特征 + 装作问题不点名事件 ID | 置零 13 个锚点相关特征，且 `anchors_of()` 一律返回空 | 22.66 | 33.10 | **73.93** | −2.62 |

结论：即使**问题里完全不出现任何事件 ID**（真实语料的常态），分数也只掉 2.6 分。
说明这套方法不是靠"问题点名事件 D005"这种生成器痕迹在拿分。

### 8.2 跨领域拆解：真正的崩塌点在哪

| 领域 | 题数 | 总分 |
|---|---|---|
| 公共安全 / 自然灾害 / 政治外交 / 经济贸易 | 1032 | **77.01** |
| 医疗健康 / 工业生产 / 社会治理 / 网络安全 | 28 | 78.8 ~ 82.0 |
| 能源环境 | 7 | 63.89 |
| 交通运输 | 7 | **41.06** |
| 科技治理 | 7 | **41.32** |

小领域的模板与大领域不同（如医疗健康是"疫情通报→官方发布→临床救治…"），但分数**没有下降**——
说明模板层面的领域偏移不是问题。真正崩掉的两个 pack 是**"真新闻风格"**的样本：

* 问题不点事件 ID，而是用中文事件名："请按时间顺序排列以下事件：事故发生、国务院成立调查组、责任追究公布……"
* 问题是事实查询/比较/概括："蚂蚁集团原计划在哪两个交易所同步上市？IPO 发行价和对应市值分别是多少？"
* 答案需要读原文，而不是套模板。

这两个 pack 就是"换到真实数据集"的迷你预演，**它们暴露了两个必须补的模块**：

1. **事件提及链接（mention linking）**：自由文本事件名 → 图节点。当前候选生成完全依赖
   `mentions()` 正则抓 `D\d{3}`，问题用中文名指代事件时直接失效。
2. **答案层**：检索 + 槽位替换依赖"答案有模板"，自由作答的题会崩。

### 8.3 哪些部分可以直接迁移，哪些必须替换

| 组件 | 迁移性 | 说明 |
|---|---|---|
| 统一 Schema 适配层 | ✅ | 换字段映射即可 |
| 因果边 pairwise 分类 | ✅ | 标准关系抽取形式，特征是通用的 |
| 链解码（候选枚举 + 学习式排序） | ✅ | 消融已证明不依赖文档顺序与锚点 |
| 按意图分流的混合专家 | ✅ | 意图标签集换成新赛题的即可 |
| 拒答 + 置信度双头 | ✅ | 阈值需要在目标集上重校准 |
| 本地 rubric 评分器 | ✅ | 方法可复制，具体权重按新赛题改 |
| 事件抽取（一文档一事件） | ⚠️ | 本赛题恰好 1:1；真实长文档需要文档级事件抽取 |
| 候选生成的"锚点族" | ⚠️ | 需补 mention linking 才能处理中文事件名指代 |
| 答案组装（检索 + 槽位替换） | ❌ | 只在答案模板化时成立，真实语料必须换成复制式生成 |

## 9. 集成"顶会思路"的实验记录

### 9.0 线上成绩与本地口径的对照（重要）

线上首版提交：**综合 72.06（A 73.74 / B 73.07 / C 58.92）**，出题方最强基线
DeepSeek-V4-Flash 是 57.61（A 67.94 / B 52.13 / C 52.75）。

| 档位 | 本地代理分 | 线上分 | 差值 |
|---|---|---|---|
| A | 77.14 | 73.74 | **−3.40** |
| B | 74.59 | 73.07 | −1.52 |

结论：本地评分器**系统性偏乐观约 1.5~3.4 分**（它自己的金标上界只有 90.36）。
以后看本地提升时按这个偏差打折，不要把本地 +1 当成线上 +1。
线上读数还说明：**B 档已经把最强基线拉开 21 分**（链解码路线有效），
而**A 档占 60% 权重却只领先 5.8 分**——提升空间压倒性地在 A 档，且 A 档内部
最弱的一环是答案（本地只有金标上界的 76%）。

三条来自文献的思路分别实现并实测（dev 1081 题，A 档口径）：

| 思路 | 文献来源 | 实现 | 结果 |
|---|---|---|---|
| 事件提及链接（多示例弱监督） | 实体链接两段式；MIL（Dietterich et al., 1997） | 同 pack 内 8~26 个候选事件，弱标签由金标链结构反推 | **保留，+0.45**（76.55→77.00） |
| 多示例软标签排序 | ListNet（Cao et al., 2007）；评测的"多条可接受链取最优" | 用 0.625·节点F1 + 0.375·顺序分 作连续目标替代 0/1 | **保留，+0.14**（77.00→77.14） |
| 作答风格路由 + 抽取式作答 | 答案句选择；MMR（Carbonell & Goldstein, 1998） | 自监督标签 = "金标答案有多少比例出现在文档里" | **组件保留、路由弃用**（负面结果，见下） |

### 9.1 提及链接为什么有用

模板题会写 `D005（调查报告）`，正则能抓；真新闻题只会说"那份调查报告"。链接器在
**弱标签口径**下 P=0.957 / R=0.926 / F1=0.942，把交通运输 pack 从 41.1 拉到 46.3。
它是"换数据集"的关键前置件：没有它，候选生成完全依赖 `D\d{3}` 这种本赛题特有的书写形式。

### 9.2 为什么软标签只有 +0.14

硬标签下正例率仅 4%，且"接近但不完全对"的候选与"完全无关"的候选一样被打成 0，
而评测恰恰给部分分（节点 F1 25 分 + 顺序 15 分）。换成连续目标后正例率 64.8%，
证据链 35.68→35.76。提升小是因为候选集的 top-1 本来就大多正确，部分分只在少数
疑难样本上起作用。

### 9.3 负面结果：抽取式作答的收益是真的，但路由学不出来

两个"真新闻风格"的 pack 上，抽取式答案明显更好（每题答案分）：

| pack | 模板式答案 | 抽取式答案 |
|---|---|---|
| 交通运输_05（7 题） | 6.59 | **17.36** |
| 科技治理_06（7 题） | 5.05 | **9.09** |

但把它接进流水线后**总分反而下降**（77.14 → 74.15）。逐题扫描、pack 级扫描都试过，
阈值越高分越高，即"越少启用越好"。根因是**自监督标签本身不干净**：我原本用
"金标答案有多少比例的字面内容出现在文档里"来判定作答风格，实测该指标在
真新闻 pack 上的中位数是 0.79、普通 pack 是 0.38——分布重叠严重（真新闻只有 43%
的样本超过 0.8，普通 pack 也有 5.6% 超过 0.8），路由学到的其实是噪声。

**结论**：组件本身有效且值得保留（配置项 `extractive_threshold` 默认 1.01 = 关闭），
但要用它必须先解决路由的监督信号问题——需要真正的"答案是否抄自原文"标注，或者用
LLM 做风格判别。这是下一步该补的，而不是继续调阈值。

### 9.4 第二轮：两个数学建模式改动

**改动一：答案槽位对齐 → 线性指派问题**

原实现是"按位置一对一替换事件 ID"，属于工程 trick。改成：
模板答案里的事件 ID 是**槽位**，把"模板槽位 → 预测链节点"建成线性指派问题
（代价矩阵 = 槽位类型提示与候选节点文本的相似度 + 位置先验），用
Kuhn-Munkres（`scipy.optimize.linear_sum_assignment`）求最小代价一一对应；
**指派代价同时用于模板重排**（对齐得越好越可能给出正确表述）。
指派问题的约束矩阵全幺模，松弛后最优解仍是整数解，所以这一步是"有最优解的建模"而非启发式。

效果：答案 23.21 → **23.49**，总分 77.14 → **77.46**。

**改动二：置信度 → 预测期望答案正确率**

评测的置信度项是 `20·(1-(conf-c)²)`，其中 c 是答案正确性。这是平方损失
（Brier 分数，proper scoring rule），其**条件最优解就是 `conf* = E[c|特征]`**。
所以正确做法不是去分类数据集标注的 certain/probable/possible，而是**直接回归答案正确率**。

两个必须注意的实现细节：

1. 训练数据必须是**诚实的预测**——如果在模型训练过的 pack 上算正确率，模型会学到
   "我永远是对的"。因此这一步放在训练流程最后，用留出的 dev 折当**校准集**
   （calibration set）跑一遍真实推理。
2. 评估时用"按 pack 分半交叉验证"保证无泄漏，得到无偏估计。

交叉验证（958 题，平均答案正确率 0.603）：

| 置信度形态 | 置信度分(满分20) |
|---|---|
| 原置信度模型输出 | 18.04 |
| 恒定 0.7 | 18.36 |
| **校准回归 E[c\|特征]** | **19.13** |
| 预言机（直接给答案分） | 20.00 |

顺带做了个风险检查：万一官方脚本是按三档（0.9/0.7/0.5）判匹配，把连续值吸附到档位
会掉到 19.14（vs 连续 19.36）。评测原文写的是"根据 confidence 与答案正确性的匹配程度"，
支持连续口径，故保留连续值。

效果：置信度 18.21 → **19.36**（注：dev 上的 19.36 略有乐观，无偏估计是 19.13）。
